# S01: smart-account-client matches Rust acceptance

Worker on `port/s01` from `ts-sdk-port`. Confirmed
[verify-b.md](verify-b.md)'s S01 residual against HEAD, then applied the T23 /
T25 standing rule: TypeScript that refuses an input Rust accepts is wrong, even
when the refusal is safer. `review-checklist.md` was not edited.

## Verdict

| Row | Verdict |
| --- | --- |
| S01 | **PARITY** |

## What was confirmed

Rust's `create_smart_account_ix` and `execute_sync_ix`
(`sdk-libs/smart-account-client/src/lib.rs`) are infallible: they return an
`Instruction` and do not validate signer sets, thresholds, uniqueness, or
packet size. Inner data length is written as `ix.data.len() as u16`, so a
buffer of `0x10000` keeps every byte and a zero length prefix. The only shared
refusals are the `checked_u8` panics on counts and compiled account indexes
past `u8`, which TypeScript already mirrors.

TypeScript alone refused the five shapes verify-b named: empty create
signers, threshold zero or above the signer count, duplicate create or
execute signers, create or execute data past `TRANSACTION_SIZE_LIMIT`, and
inner data at `0x10000`. Each was confirmed against the sources before the
checks were removed. None of them fails later in Rust's builders; the caller
gets an instruction in both languages.

## What changed

`createSmartAccountInstruction` and `executeSyncInstruction` drop the
TypeScript-only refusals. Integer-domain checks that mirror Rust's types
(`u16` threshold, `u32` time lock, `u8` permission mask) stay. Payload
compilation still refuses a compiled account index past `u8`, matching
`checked_u8`. Inner data longer than `u16` now truncates the length prefix
with `& 0xffff` and still appends the full buffer, matching `as u16`.

Pinned in `smart-account-client/test/boundaries.test.ts`: empty, duplicate,
and out-of-range-threshold create sets construct; duplicate execute signers
construct; create and execute data past 1232 bytes construct; an inner buffer
of `0x10000` carries a zero `u16` prefix and the original bytes. Shared `u8`
count refusals are unchanged.

## Control edits

Each new acceptance case was reddened once and reverted:

- Re-adding the empty-signer throw failed the create acceptance case.
- Re-adding the threshold-zero throw failed on `create({ threshold: 0 })`.
- Re-adding the threshold-above-count throw failed the same case on the empty
  set (threshold 1 with zero signers).
- Re-adding create and execute duplicate-signer throws failed both duplicate
  acceptance cases.
- Re-adding the 1232-byte payload and instruction size throws failed the
  oversized acceptance case.
- Re-adding the `SMART_ACCOUNT_DATA_TOO_LARGE` throw failed the `0x10000`
  truncation case.

A temporary Rust unit test on the same shapes, including the length-offset
bytes for `0x10000`, passed against `lib.rs` and was removed so the commit
stays on the TypeScript side.
