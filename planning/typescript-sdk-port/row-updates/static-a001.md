## Job two: optional merge tree selector (A001 ruling)

Finding A001 claimed TypeScript lagged Rust on a public tree selector. That was
WRONG: `MergeParams` had no `tree` in either language. The real shared gap is
that both refuse once more than one tree holds the asset, with no way to
disambiguate after a rollover.

Per `authority-rulings.md` section A001, both SDKs gained an optional selector
now.

### Shape

| Language | Field |
|----------|--------|
| Rust `MergeParams` | `pub tree: Option<Address>` |
| TypeScript `MergeParams` | `readonly tree?: Address` |

Omitted selector preserves today's behaviour, including `AmbiguousTree` /
`WALLET_MULTIPLE_INPUT_TREES` when holdings straddle trees. When set, auto-sweep
and explicit-hash selection both filter to that tree. A named hash on another
tree still raises `InputUtxoTreeMismatch` / `WALLET_INPUT_UTXO_TREE_MISMATCH`
with both trees in the details.

### Evidence

- Rust unit tests: `create_merge_tree_selector_disambiguates_a_rollover`,
  `create_merge_tree_selector_rejects_a_mixed_tree_explicit_hash`
- TypeScript unit coverage in `wallet.test.ts` (same three behaviours)
- Cross-language vector: `sdk-libs/ts/vectors/wallet-actions-v1.json` `merges`
  section, generated by `cargo run -p xtask --bin wallet-actions`, replayed in
  `wallet-actions.test.ts`

### Compile sites outside sdk-libs

`MergeParams` construction in `cli` and `xtask` was updated with `tree: None` so
the workspace still builds. No CLI `--tree` flag was added (out of the
sdk-libs-first scope).
