## Job one: close the untested arms

Row W03 was already `PARITY` on behaviour after the `a3ecf6a9` re-review. The
cell itself admitted two untested arms:

1. The three `validate_merge_submission` key-mismatch codes (signing-rail,
   nullifier, viewing).
2. Indexer proof-tree rejection (`ensure_proofs_match_submit_tree` /
   `treeCheckedIndexer`) when a returned proof names the wrong state or
   nullifier tree.

### Evidence added

| Piece | Path |
| --- | --- |
| Oracle generator | `xtask/src/bin/wallet-submit.rs` |
| Vector | `sdk-libs/ts/vectors/wallet-submit-v1.json` |
| TypeScript replay | `sdk-libs/ts/wallet/test/vectors/wallet-submit.test.ts` |

The generator calls the real Rust functions
`validate_merge_submission` and `ensure_proofs_match_submit_tree` (now `pub` on
`sdk-libs/wallet/src/actions/submit.rs`) over a fixed ed25519 seed. TypeScript
rebuilds that identity via `ShieldedKeypair.fromEd25519` and replays the cases
through `submitMergeTransaction`.

### Key-mismatch results

Rust and TypeScript agree on the three recorded cases:

| Case | Rust `ClientError` | TypeScript `WalletError` |
| --- | --- | --- |
| signing-rail (P256 slot on ed25519 owner) | `MergeSigningKeyMismatch` | `WALLET_MERGE_SIGNING_KEY_MISMATCH` |
| nullifier pubkey drift | `MergeNullifierKeyMismatch` | `WALLET_MERGE_NULLIFIER_KEY_MISMATCH` |
| viewing pubkey drift | `MergeViewingKeyMismatch` | `WALLET_MERGE_VIEWING_KEY_MISMATCH` (with `owner` detail) |

### Indexer proof-tree results

| Case | Outcome |
| --- | --- |
| matching state + nullifier trees | accepted by the tree check |
| wrong state tree | `WALLET_MERGE_TREE_MISMATCH` with Rust's `proofTree` / `submitTree` |
| wrong nullifier tree | same |

One case also runs through real `ZolanaClient.proveMerge` so the wallet
rejection is not erased when the assembler wraps unknown throws. That required a
small client fix: `assembleMerge` / `assembleMergeZone` now preserve
caller-supplied coded errors (via `propagateAssemblerCause`) instead of turning
them into `CLIENT_UNEXPECTED`.
