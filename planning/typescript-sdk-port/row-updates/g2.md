# G2 compress: gnark Fq2 limb order (port/g2)

Worktree `zolana-ts-g2`, branch `port/g2`. Scope: `sdk-libs` + `xtask`.
Adopted from commit `7c976046` on `origin/ts-example-deposit-transfer-withdraw`.

## Root cause (one sentence)

`compressG2` read each gnark Fq2 coordinate as `c0` first while gnark writes `c1` first (`x.c1 || x.c0 || y.c1 || y.c0`), so noble's curve check ran on a different, genuinely off-curve point and every live prover B failed with `equation left != right`.

## Why validation looked right

noble's `assertValidity` was correct about the point it was handed. The defect was parsing (limb order), not a twist-convention mismatch and not a deliberate TypeScript fail-fast policy. Deleting the check alone would have hidden the byte-order bug and let malformed points through; the fix reads limbs in gnark order for the sign bit and then drops the curve check so compression matches `alt_bn128_g2_compress_be`.

## Fix (from `7c976046`)

1. `compressG2` in `sdk-libs/ts/client/src/prover/proof.ts`: keep the field-range check the syscall performs; drop `bn254.G2.Point.fromAffine(...).assertValidity()`; take the sign from `y1` then `y0` (Fq2 orders on `c1`; `c0` only decides the sign when `c1` is zero). Off-curve points are left for the on-chain verifier.
2. Fixture generator `proof-response-parity`: emit `bs` as `(A1,A0)` to match the prover. Regenerated `proof-response-parity-v1.json`. Synthetic off-curve G2 is now `off-curve-g2-compress-shared-accept` with disposition `match-syscall-range-check`.
3. Local stack (same commit): find the repo root without a fixed parent walk from `import.meta.url`; omit Photon's `--db-url` and set per-stack `TMPDIR` so migrations run and concurrent stacks do not share a DB.

## What this is not

- Not a twist mismatch between noble and gnark.
- Not a rail-level policy divergence between TypeScript and Rust.
- Not a reason to keep a client-side G2 curve check at compress: only the sign of `y` is read, and Solana's compressor does no curve check.
