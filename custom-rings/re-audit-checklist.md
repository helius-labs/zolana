This review covers `alex/ve2-merge` after `aa2273c60` and the integration of [PR #427](https://github.com/helius-labs/zolana/pull/427) at `9d751d67c06dfeacf3e4d111c7a1866f2c280142`. It also checks the October 2026 Certora draft supplied with the review. That draft starts from `0125d8a` and does not certify this custom-ring branch.

The previous findings are not all still open. Recovery-key enforcement, authoritative auditor openings, upgrade checks and curator retries have changed. PR #427 also closes the merge recovery problem. This review fixed data-trust, account-authorization and pagination defects. Fourteen specialized policy shapes now settle with valid proofs after PR #427. The remaining shapes still need the matching ordinary transfer keys before approval.

Specialist passes covered registry writes, recovery, constraints, on-chain authorization, release tooling, integration, clients, documentation and the Certora circuit changes. Reviews ran in waves within the available worker limit. Each included source reading. The checks below distinguish that reading from executed tests.

Two additional trust boundaries needed repair.

Key registration proves that existing list bits stay unchanged. Its public statement does not include the redundant list fields in the instruction. Photon used those fields when projecting the row. Incorrect redundant values could make it reject an otherwise valid registration and quarantine the ring projection. [The projection](../services/photon/src/custom_rings/member_registry.rs) now retains the authenticated stored bits and still requires the reconstructed root to match the proven new root. Ordinary list updates continue to check their supplied old and new bits. The regression exercises the storage transition without generating or modifying a live proof.

Recovery also copied optional recipient `utxoData` and memo fields into spend objects. Delegate and merge selection can reject those fields even when the proved data hash is zero. Both clients now preserve the authenticated hashes and discard optional recipient metadata in recovered spend objects. Regression cases cover malformed delivery, false optional metadata, an unseen first merge input and unknown mints. Commitment verification happens before a missing mint is reported.

The ring forwarder gives its PDA a signature in the SPP CPI. Checking only the outer fee payer left other forwarded accounts able to gain that signature. [The transfer path](program/src/instructions/transact.rs) now requires each owner signer to have signed the outer instruction. [Public-leg parsing](program/src/instructions/public_legs.rs) also checks every SOL deposit source and SPL token authority in every settlement group before the CPI. Negative tests include a PDA alias in each role. This closes a conditional unauthorized-debit and note-owner path. It does not depend on the payer also being the owner.

PR #427 excludes the fee payer from SPP's anonymous public owner-signer vector. Both Rust construction paths used the payer hash in slot zero. Native proof generation therefore produced a statement the on-chain verifier would reject. The anonymous public vector is now empty. The Go request fixture changes only that vector and its derived public hash. Nine anonymous shapes now pass actual settlement.

Rust recovery now records an unknown audited-deposit mint as unresolved after checking the raw mint against the committed note. It continues scanning other deposits. The TypeScript auditor stops on a terminal `scannedThrough` even when the page also includes a cursor, and rejects invalid page bounds. Ring RPC applies the same terminal rule and returns each transaction's authenticated event index. Its clients can distinguish two events with one signature.

The follow-up circuit findings exposed one more missing relation. A ring merge authenticated each input's ring-data hash and the carried output hash, but did not require them to match. [The ring wrapper](../prover/server/circuits/spp_merge/ring.go) now requires every real input to carry the output's hash. Dummy padding is exempt. Both SDKs infer the common hash and reject mixed inputs or a conflicting output override before proving. This preserves recovery and application state. The three ring-merge setups were regenerated and checked against the exact compiled circuits. Each loaded key generated a proof that passed native verification. Default merge constraints stay unchanged.

No owner signature is added to consolidation. The merge proves knowledge of the nullifier secret and authenticates the same owner in every real input commitment. It preserves that owner, the asset and the total amount. Application-data hashes are fixed to zero. M-03 makes the result recoverable by that owner. The ring program still authorizes its merge CPI and enforces its own controls. Anonymous reference rings reject this route because it has no anonymous auditor disclosure.

Live validation exposed a separate construction limit. A custom merge with 51 real inputs needs 4,114 bytes in the minimal tested layout. The v1 limit is 4,096 bytes. The earlier 51-input cap counted account addresses but missed the byte limit. Both SDKs now cap custom merges at 50 real inputs. The 52-slot circuit pads the remaining slots. Extra accounts or signatures can lower that limit further. Both SDK flows serialize the real account layout with fixed-width proof placeholders before proving. Final assembly checks the complete transaction again. A 50-input merge with an extra co-signer fails the preview. The 49-input co-signed layout fits.

The reported zero-asset gap is already covered by [the shared merge output check](../prover/server/circuits/spp_merge/shared/outputs.go). It calls the transaction output constraints with an always-real output. Those constraints reject a zero asset field. The new regression targets that relation directly. SOL's zero mint address is valid because it hashes to a nonzero asset field.

SDK preflight now blocks the default-output footgun. On the confidential ring rail, an unmarked output publishes an owner hash of zero. A real default-ring output must instead use its explicit exit marker and correct owner tag. The Rust and TypeScript preflights enforce that agreement before proving, including raw and indexed proof requests. Real zero-amount notes still need a marker. Dummy padding does not. Raw field values must be canonical before this classification. A modulus-sized value cannot masquerade as a nonzero identity and then reduce to zero in the circuit. This protects wallet construction without changing the intentional boundary around unproved ordinary recipient encryption.

`hash_bytes` still has no length tag. A 32-byte input and a 33-byte input can occupy the same hash namespace. The source and spec now warn against comparing those different roles for identity or authorization. This review does not introduce such a comparison or change existing address encodings.

[The shared structural suite](../prover/server/circuits/spp_transaction/shared/structural_test.go) applies one mutation corpus to the default, confidential ring, anonymous and authority wrappers. It covers data-bearing output authorization, packed input flags, tree selection, canonical compact padding, balance and public-slot rules. Anonymous tests also reject both message-hash limbs at or above `2^128`. Nonhidden input owners must be public signers on owner-signed rails. The authority rail deliberately delegates that authorization to its calling program. Positive controls preserve that distinction. The suite rebuilds commitments and signatures where needed so stale hashes do not substitute for the intended rejection.

Merge ciphertext is owner-recovery encryption. It is separate from the auditor disclosure required for transfers and audited deposits. An audit-only ring's auditor key cannot decrypt it by itself. Escrow recovery can decrypt it when the registered nullifier secret is available. Ring merges are discovered through spent nullifiers, not the auditor-tag scan. A later transfer still requires the normal auditor disclosure.

The requested Poseidon mask is included in M-03. Each ciphertext field adds a domain-separated Poseidon pad to the committed amount or mint chunk. Recovery subtracts the pad and checks the reconstructed commitment. This is separate from I-07's HashChain4 length-binding limitation.

The proof review followed the composition boundary, not only individual gadgets. SPP verifies ownership, inclusion, nullifiers and conservation. The custom proof reconstructs the same private transaction hash from the fields it screens and discloses. The program builds the public table from its owned account. Shape, mode and rail come from the selected verifier. Shared registry paths authenticate every queried leaf and require the complete aligned frontier. General paths remain available for scattered records.

The focused arithmetic review covered canonical field bytes, ordered absence, sparse frontiers, integer comparisons, carries, division hints, X25519 encodings and AES bindings. Tests include invalid witnesses at those boundaries. The BSB22 commitment proof remains required by the verifier dependency. No missing constraint was found in those inspected paths. That is evidence for the reviewed relations, not a formal proof of the whole system.

[The obligation map](audit-readiness.md) connects each guarantee to its circuit, program checks, client consumer and regression tests. [The policy walkthrough](../prover/server/custom_rings/circuits/policy/doc.go) now explains the full constraint order and its assumptions. The default transaction walkthrough remains a useful reference. Stale private-hash comments were corrected. The private hash excludes external data, which the outer public statement binds separately.
