# SPP proving benchmarks

Results written by `scripts/bench_spp.sh` (`just prover bench-spp`, or
`just prover bench-spp-all` for every supported shape), which runs
`BenchmarkSppTransfer` over the four spp_transaction variants:

| Variant | Circuit |
|---|---|
| `confidential` | default-zone, output owners bound to public tags |
| `zone` | custom-zone transfer, owners private |
| `zone_authority` | anonymous zone-authority transfer, no owner signature |
| `p256` | custom-zone transfer with the emulated P256 gadget |

One timed operation is one server-side proof: `ProveTransfer` /
`ProveP256Transfer`, i.e. witness assembly plus `groth16.Prove`. Circuit
compilation and Groth16 setup are excluded. `BenchmarkSppWitness` measures
witness assembly alone (well under 1% of a proof) when a regression needs
attributing.

Since the EdDSA-Poseidon spend-authority change, the keys are generated by a
local `groth16.Setup` instead of loaded from the committed set: the transfer
circuits gained private inputs, so no pinned key can prove their witnesses. A
locally set up key has the same structure as a committed one, so timings stay
comparable to the committed-key rows recorded before the change. Note that
`groth16.DummySetup` is NOT usable here -- it fills every curve point of the
proving key with the same value, and multi-scalar multiplication over identical
points ran 27% faster than over the distinct points of a real key.

Every combination is checked against `prover/fingerprint.Pinned` before it is
timed, so a row can never be attributed to a circuit other than the pinned one.
`prover/fingerprint.KeyPinned` and `KnownKeyDrift` are empty while the committed
keys do not match these sources; they fill back in after the next key rotation.

Results are newest first: the script inserts each run directly below the marker.
