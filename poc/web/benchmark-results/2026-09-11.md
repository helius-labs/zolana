# Transfer 2×3 browser benchmark — 2026-09-11

The midrange-device target is not validated. These measurements use the actual
54,031-constraint transfer circuit on a Ryzen 9 9950X desktop (Linux, Chromium
153.0.8010.12). A browser with fewer workers is not a phone measurement.

## Shipped Arkworks build

One fresh session per worker setting, three warmups and 30 measured proofs.
Preparation and verification are separate. P95 uses nearest rank and retains
outliers. All proofs use the same pinned key and public sample.

| Workers | First proof, ms | Proof p50, ms | Proof p95, ms | Maximum, ms |
| ---: | ---: | ---: | ---: | ---: |
| 2 | 2629.4 | 2593.3 | 2600.1 | 2600.3 |
| 4 | 1505.1 | 1481.0 | 1496.9 | 1506.5 |
| 8 | 957.1 | 924.8 | 960.9 | 969.9 |
| 16 | 703.6 | 681.7 | 716.2 | 719.8 |

Key preparation was approximately 13.7 seconds. Only the 8- and 16-worker settings
passed p95 < 1,000 ms in this desktop session; 8 workers left little margin.
This does not select an optimal pool size for a phone.

## Diagnostic phases

A separate instrumented build uses the same circuit, key and Arkworks arithmetic.
Go timers are opt-in with `bench_profile`; Rust timers use `bench-profile`.
The production benchmark above uses the ordinary build. Values below are medians
in milliseconds. Nested timers and concurrent MSM times cannot be added.

| Phase | 8 workers | 16 workers |
| --- | ---: | ---: |
| Witness construction | 0.40 | 0.41 |
| Go solve, including commitment hints | 230.50 | 220.05 |
| Main MSM wall time | 635.59 | 425.61 |
| FFT | 37.79 | 28.32 |
| Proof assembly | 2.68 | 2.66 |
| Request decoding / lookup | 0.60 | 0.62 |

MSMs and the Go solver dominate. Witness construction, JSON parsing and Rust
input decoding are individually below 1 ms here. Increasing the arithmetic pool
does not parallelize the Go solver. Improving key preparation does not improve
proof-generation time.

## Device acceptance

Use the separate `/benchmark.html` page on the target physical device. Record its
model, browser, worker count, first-proof latency, and three sessions of 30 timed
proofs. Require proof p95 below 1,000 ms in each session. Keep the tab visible;
backgrounding or cancellation invalidates a run. Reports download locally and
contain all timing samples and the public sample's proofs, without witness bodies.
No phone, Safari or Firefox measurements have been made for this report.

## Validation and evidence

- 264 browser proofs independently checked by native gnark across four baseline, two Rust-profile and two combined-profile sessions (including warmups).
- Core tests and type checks passed; native prover tests passed with and without diagnostic timers.
- Mobile layout, cancellation and hidden-tab cancellation were checked in desktop Chrome. This validates UI behavior, not mobile proving speed.
